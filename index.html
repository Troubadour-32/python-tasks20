Как вывести результат теста в PyQt5

Конспект к программе «Memory Card». Собираем логику «Ответить / Показать результат»

Главная идея: интерфейс уже нарисован. Нам осталось связать кнопку btn_OK с функцией, которая решает: показать вопрос или показать результат.

1Что уже готово в программе

В файле созданы два контейнера типа QGroupBox:

  • RadioGroupBox — «Варианты ответов». Внутри четыре переключателя QRadioButton: rbtn_1 … rbtn_4.
  • AnsGroupBox — «Результат теста». Внутри два QLabel:
    • lb_Result — сюда пишем «Правильно!» или «Неверно!»;
    • lb_Correct — сюда пишем текст правильного ответа.

Сейчас AnsGroupBox скрыта, а RadioGroupBox показана. Значит, по нажатию кнопки нужно переключать видимость этих панелей и заполнять надписи.

2Заводим данные о правильном ответе

Правильные ответы — это данные, а не часть интерфейса. Их удобно держать отдельно, чтобы потом добавить несколько вопросов.

Пока в программе нет информации о том, какой вариант верный. Нужна переменная-состояние. Проще всего — словарь, где хранится номер правильного варианта и его текст. Номер считаем с нуля: 0 — первый, 1 — второй и так далее.

Объяви этот словарь после создания всех виджетов, но до функции-обработчика.

# словарь с данными текущего вопроса question_data = { 'correct_index': 2, # номер правильного варианта (0..3) 'correct_text': 'Вариант 3' # что показать в lb_Correct }

3Флаг режима: вопрос или результат

Кнопка должна работать в двух режимах. Чтобы функция понимала, в каком она сейчас, заведи переменную-флаг рядом с данными:

# False — показан вопрос, True — показан результат answer_shown = False

При каждом нажатии мы будем её переключать. Это позволяет обойтись одной функцией на оба режима — так код короче и понятнее.

4Пишем функцию-обработчик

Функция — обычная функция Python без аргументов. Внутри — развилка по флагу.

4.1. Ветка «показать результат»

Срабатывает, когда answer_shown == False, то есть сейчас виден вопрос. Порядок действий:

  1. Определи, какой переключатель выбран. У QRadioButton есть метод isChecked(), он возвращает True или False. Проверяешь по очереди все четыре и запоминаешь номер выбранного (или -1, если ни один не выбран).
  2. Если ни один не выбран — просто return. Ничего не ломается, панели не переключаются.
  3. Сравни номер выбранного с question_data['correct_index'].
  4. Заполни lb_Result через setText(): «Правильно!» или «Неверно!».
  5. Заполни lb_Correct текстом правильного ответа.
  6. Спрячь RadioGroupBox методом hide() и покажи AnsGroupBox методом show().
  7. Поменяй надпись кнопки: btn_OK.setText('Следующий вопрос').
  8. Переключи флаг: answer_shown = True.
Важно: чтобы менять переменную answer_shown внутри функции, в начале функции нужно написать global answer_shown. Иначе Python создаст локальную переменную и флаг снаружи не изменится.

Скелет ветки — примерно такой (собери сам, подставляя свои имена):

def check_answer(): global answer_shown if not answer_shown: # 1) ищем выбранный вариант selected = -1 if rbtn_1.isChecked(): selected = 0 elif rbtn_2.isChecked(): selected = 1 elif rbtn_3.isChecked(): selected = 2 elif rbtn_4.isChecked(): selected = 3 # 2) ничего не выбрано — выходим if selected == -1: return # 3) сравниваем с правильным if selected == question_data['correct_index']: lb_Result.setText('Правильно!') else: lb_Result.setText('Неверно!') # 4) показываем правильный ответ lb_Correct.setText(question_data['correct_text']) # 5) переключаем панели и кнопку RadioGroupBox.hide() AnsGroupBox.show() btn_OK.setText('Следующий вопрос') answer_shown = True

4.2. Ветка «вернуться к вопросу»

Срабатывает, когда answer_shown == True, то есть сейчас виден результат. Действия:

  1. Спрячь AnsGroupBox, покажи RadioGroupBox.
  2. Верни надпись кнопки: btn_OK.setText('Ответить').
  3. Сбрось все переключатели: у каждого из rbtn_1 … rbtn_4 вызови setChecked(False).
  4. Переключи флаг обратно: answer_shown = False.

Эта ветка — else к той if not answer_shown, что в предыдущем блоке. Собери её по образцу, только с обратными действиями.

5Подключаем кнопку к функции

В PyQt5 события подключаются через сигнал clicked и слот — обычную функцию Python. Строка подключения выглядит так:

btn_OK.clicked.connect(check_answer)

Куда её ставить: после объявления функции check_answer и до вызова app.exec(). Причина: app.exec() запускает цикл событий и блокирует строку, пока окно не закроют. Всё, что написано после него, выполнится только при закрытии окна — поэтому подключение сигнала должно быть раньше.

6Порядок в файле

Собери куски в таком порядке — тогда не будет ошибок вида NameError:

  1. Импорты и app = QApplication([]).
  2. Создание всех виджетов (кнопка, вопрос, переключатели, панели).
  3. Компоновка (layout'ы).
  4. Словарь question_data и флаг answer_shown.
  5. Функция check_answer.
  6. btn_OK.clicked.connect(check_answer).
  7. window.show() и app.exec().

7Типичные ошибки

ОшибкаПочему плохоКак правильно
Функция объявлена после connect Python выбросит NameError Объяви функцию до подключения сигнала
Нет проверки, выбран ли вариант Сравнение с «ничем» даст неверный результат Сначала проверь isChecked(), если ни один — return
Забыл AnsGroupBox.show() Пользователь не увидит результат Не забудь про show() и hide() у обеих панелей
Не сброшены переключатели при возврате Старый выбор остаётся, можно случайно нажать «Ответить» с прежним вариантом Пройдись по rbtn_1..rbtn_4 и вызови setChecked(False)
Нет global answer_shown Флаг снаружи не изменится, режимы не переключаются Первой строкой функции напиши global answer_shown
Сравниваешь объекты QRadioButton вместо номеров Сравнение объектов не даст нужного результата Сравнивай индексы 0..3 или строки ответов

8Чек-лист проверки

  • Запустил программу — видна панель вариантов, панель результата скрыта.
  • Нажал «Ответить» без выбора — ничего не сломалось, панели не переключились.
  • Выбрал верный вариант — появилось «Правильно!» и текст правильного ответа.
  • Нажал кнопку ещё раз — снова панель вариантов, галочки сняты.
  • Выбрал неверный вариант — появилось «Неверно!» и текст правильного ответа.
  • При повторном показе вопроса можно выбрать другой вариант и получить другой результат.

9Куда двигаться дальше

Когда базовый сценарий работает, можно расширять:

  • завести список вопросов (каждый — словарь с полями question, answers, correct) и переключаться по кнопке «Следующий вопрос»;
  • считать счёт правильных ответов и показывать его в конце;
  • вынести данные вопросов в отдельный файл (например, JSON) и загружать при старте.

Но сначала добейся стабильной работы одного вопроса — это фундамент для всего остального.
